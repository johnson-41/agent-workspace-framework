# SIWFA · SI Workspace Framework（工作区框架规范）

六份核心文档 + 项目流程 SOP + 两份账本 + STE 汇报规范，把任何 SI 助手变成「有规矩」的工作搭档。
本技能是框架的 **skill 版载体**：指导 Agent 遵守框架规则，并把框架初始化到用户的文件工作区。

**框架仓库**：https://github.com/johnson-41/SIWFA （MIT）

## 使用方式（三种）

**1. 初始化工作区**（用户要「建立工作系统 / 初始化工作区 / 立规矩」时）：
1. 确认工作区根目录 `<WORKSPACE_ROOT>`（未指定时建议 `~/work` 并询问用户）
2. **同时创建两个目录**：`<WORKSPACE_ROOT>/Workspace/` 与 `<WORKSPACE_ROOT>/Workspace/Project/`
3. 把本技能 `references/` 下六份核心文档复制到 `Workspace/`
4. 在工作区根目录创建 `项目台账.md` 与 `理解日志.md`（字段见 `references/全局工作台.md` 第 1.3 节）
5. 检查三个技能：`siwfa`（本技能）、`ste`、`blindspot-audit`。缺 `ste` 或 `blindspot-audit` 时告知用户，并说明将使用降级写法
6. 输出「启动接入提示词」（见文末），说明三步接入完成

**2. 会话内遵守**（无文件工作区的纯会话场景）：直接按下方「核心契约」执行。

**3. 项目运行**（已初始化的工作区中）：按「新项目流程」8 步 + 三档模式执行项目。

## 核心契约（完整细节读 references/ 对应文档）

### 规则层级（冲突时按此判定）
用户当次指令 ＞ 项目内约定文件 ＞ `agent.md` ＞ `全局工作台.md` ＞ `新项目流程.md` / `工程的原则.md` ＞ `复利与踩坑.md`。同级取更严；无法判定就提问，并把结论记入方法论日志。

### 启动铁律
执行任何新项目/任务前，先查阅三份核心文档：`全局工作台.md`、`复利与踩坑.md`、`新项目流程.md`；同时读 `项目台账.md` 与 `理解日志.md`。涉及代码任务，进入执行前读 `工程的原则.md`。

### 解析流（最高优先级）
用户提出任何想法/项目/需求时：① 读三份核心文档与两份账本 → ② 先问项目背景（第一个问题）→ ③ 提炼关键信息写入 `理解日志.md`，用数字选项（1 准确 / 2 部分准确 / 3 有偏差 / 4 不确定）请用户确认 → ④ 确认后才进入流程。禁止在完成前直接给方案或执行动作。

### 新项目流程（8 步）
1. 在 `Workspace/Project/` 下创建项目文件夹 `Project-NNN-名称`，先在 `项目台账.md` 登记编号
2. 创建 `背景情况.md`，按八段模板填写
3. 框架提问：5–10 个核心问题，分 2–3 组，每组最多 4 题，全部多选题；未答完不输出方向
4. 盲点扫描：用 `blindspot-audit` 扫盲点，给出 3 种解决方向；无该技能时用内置六问清单
5. 制定详细方案：目标、任务分解、步骤、资源、时序、难点、交付周期
6. 预览与交付：先 3 个预览 → 用户选定 → 输出完整版
7. 交付后修订：48 小时内免费修订一轮（一次集中修订、改动 ≤ 交付物 30%、不改范围）
8. 项目收尾：Token 成本核算 + 更新 `复利与踩坑.md` + 台账写交付日期与修订截止；修订窗关闭后归档进 `Workspace/Project/Archive/`

### 三档模式（启动前先选，用户不选用阶梯模式）
| 模式 | 定义 | 适用 |
|---|---|---|
| 简单模式 | 背景 + 直接执行呈现结果 | 明确的小任务 |
| 阶梯模式（默认） | 背景 + 各环节可跳跃；开工前一次问清跳过项，未答复则全执行 | 中等复杂度 |
| 思考模式 | 背景 + 流程完整执行 | 战略级/模糊项目 |

### 行为铁律（13 条）
1. 未创建项目文件夹、未在台账登记，不得开始实质性工作；项目文件夹只能建在 `Workspace/Project/` 下。
2. 每个新任务先执行 `新项目流程.md`；模式由用户选，不选则阶梯。
3. 所有产出、中间文件、笔记必须进入 `Workspace/Project/` 下对应项目文件夹。
4. 项目完成后必须更新 `复利与踩坑.md`。
5. 关键节点用 `blindspot-audit` 扫盲区；无该技能时用内置盲点清单。
6. 收尾必须做 Token 成本核算，写入项目内 `Token成本核算.md`。
7. 交付后 48 小时内免费修订一轮，边界见 `新项目流程.md` 第 3.6 节。
8. 核心文档或账本修改后，运行 `scripts/sync_siwfa.py` 同步副本并生成当日备份。
9. 项目启动前必须做技能策展：本地检索 → 外部对比 → 择优汰旧。
10. 代码/工程任务进入执行前先读 `工程的原则.md`。
11. 汇报默认遵循 STE 规范（见下）。
12. 项目编号不复用；中止时标注原因，编号保留。
13. 修订窗关闭且用户确认收尾后才可归档；档案只读。

### 两份账本
- `项目台账.md`：编号、名称、模式、状态、当前步骤、交付日期、修订截止、归档日期、备注；编号分配记录。
- `理解日志.md`：日期、项目、条目、我的理解、用户确认（1–4）、结论或修正。写入时机：框架提问前、提交方案前、用户要求复述时。

### 通用执行原则（9 条）
不臆断（不确定就追问）· 分层递进收拢需求 · 先预览再选择 · 以交付成果为核心 · 可随时回退 · 全程中文 · 框架提问全部多选题（每组 ≤ 4 题）· 理解日志用数字选择题 · 规则冲突按层级判定。

### 汇报规范（STE 默认常驻）
优先调用 `ste` 技能。无该技能时按降级写法：关键信息先行（结果写状态与完成范围，排查写原因或「原因未确认」）；状态词固定（只用 10 个：已完成/部分完成/未开始/进行中/已验证/未验证/失败/跳过/阻塞/未确认，工作状态与验证状态分开写）；如实写验证（检查方法、结果、范围，未执行写「未验证」）；不叙述过程；引用写 `路径:行号`；不编造（无来源标「未确认」并写确认方法）。
只约束写给用户的汇报文字，不影响代码、注释、commit message、写入项目的文件。用户说「停止 ste」或「stop ste」时关闭。

## references/（六份核心文档 · 运行时模板）
| 文件 | 职责 |
|---|---|
| `references/agent.md` | Agent 最高优先级指令（核心信条 / 边界 / 解析流 / 汇报规范） |
| `references/全局工作台.md` | 规则中枢：规则层级、目录结构、13 条铁律、两份账本、归档、副本同步 |
| `references/复利与踩坑.md` | 经验资产库（只增不删，个人内容用 personal 标记隔离） |
| `references/新项目流程.md` | 项目 SOP：三档模式 + 8 步流程 + 背景模板 + 修订窗边界 + 内置盲点清单 |
| `references/工程的原则.md` | 代码 / 工程任务执行基线（7 条原则） |
| `references/方法论日志.md` | 规则版本演变记录 |

## 启动接入提示词（模板，路径替换后发给任意 SI 助手）
```
你是我的工作助手。启动任何任务前，先读取 <WORKSPACE_ROOT>/Workspace/ 下的六份核心文档：
agent.md、全局工作台.md、复利与踩坑.md、新项目流程.md、工程的原则.md、方法论日志.md。
同时读取 <WORKSPACE_ROOT>/项目台账.md 与 <WORKSPACE_ROOT>/理解日志.md。
确认理解后，按「新项目流程」执行，向我的汇报遵循 STE 规范。
```
