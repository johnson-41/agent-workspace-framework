# 复利与踩坑

> 版本 v1.3 ｜ 2026-10-26 ｜ 变更：补 1 条目录重构经验

**定义**：经验资产库，记录踩过的坑、沉淀可复用的方法。

**解决**：同样的坑反复踩，好方法不沉淀。

**目标**：形成复利效应，每完成一个项目就积累一次经验。

### 2.1 使用规则

- 任何项目结束（交付/中止/复盘）后，立即补一条「踩坑」或「复利」记录。
- 记录要具体：背景、发生了什么、根因、学到的、下次怎么做。
- 只增不删：记录作废时标记删除线并注明原因，不物理删除。
- 重大经验应反向更新 `新项目流程.md` 或 `全局工作台.md`。
- 个人环境与账号相关的记录，用 `` 包裹，避免同步到公开副本。

### 2.2 结构

**踩坑记录**（表格）：日期、项目、坑点描述、原因、解决办法、教训/预防。

| 日期 | 项目 | 坑点描述 | 原因 | 解决办法 | 教训/预防 |
|---|---|---|---|---|---|

**可复用方法 / 模型 / 模板**：
- 框架提问法：目标/需求/受众/范围/时间等核心问题逐一定问，三档模式，每组最多 4 题。
- 盲点三维扫描：blindspot-audit 扫盲点，给出三种解决思路；无技能时用「内置盲点清单」六问。
- 预览锁定交付：先 3 个预览，选定再出完整版，避免 token 浪费。
- 命名即规范：`Project-编号-名称`，无例外。
- 技能策展：启动前检索技能库，择优汰旧，结果写进背景情况。
- Token 成本核算：收尾记录预估与实际消耗。
- 交付后修订窗口：48 小时内免费修订一轮；一轮 = 一次集中修订、改动不超过交付物 30%、不改范围。
- STE 汇报规范：汇报默认遵循 STE，只约束表达不影响产物。
- 双账本：`项目台账.md` 管编号与状态，`理解日志.md` 管理解与确认，避免撞号与误解。
- 单真源同步：一份真源 + 同步脚本 + 个人内容标记，替代手工维护多副本。

**行为规范补充**：
- 选项编号铁律：选项序号用数字（1/2/3/4），不用字母（A/B/C/D）。
- 汇报规范边界：STE 只约束 Agent 写给用户的文字，不约束代码、commit、项目文件。
- 引用即校验：规则里出现的每个文件名、技能名，必须存在于工作区或技能库，或明确标注「需安装」。

**走过的弯路**：
- 信息不全给方案 → 先框架提问收敛。
- 文档散落 → 强制归入项目文件夹。
- 命名反复调整 → 已统一连字符格式。
- 规则引用未定义概念（理解日志、备份文件） → 本次补齐定义与格式。
- 多副本靠手工同步 → 改为脚本同步。
