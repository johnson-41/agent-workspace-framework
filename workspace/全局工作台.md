# 全局工作台

> 版本 v1.3 ｜ 2026-10-26 ｜ 变更：项目目录统一归入 `Workspace/Project/`，新增工作区初始化要求

**定义**：工作系统的规则中枢，一切规则的总入口。

**解决**：文档散落、命名混乱、行为无红线、产出不可追溯。

**目标**：让所有工作有章可循，产出可追溯，方向不偏航。

### 0.1 适用范围

本文件约束 Agent 在 `<WORKSPACE_ROOT>` 内的一切工作。用户在当次对话中明确给出的指令，优先级高于本文件。

### 0.2 规则层级（冲突时按此判定）

| 层级 | 来源 | 说明 |
|---|---|---|
| 1 | 用户当次明确指令 | 最高，可直接覆盖下文任何规则 |
| 2 | 项目文件夹内的约定文件 | `背景情况.md`、项目内 `CLAUDE.md` 等 |
| 3 | `agent.md` | Agent 最高优先级指令 |
| 4 | `全局工作台.md` | 本文件 |
| 5 | `新项目流程.md`、`工程的原则.md` | 专项规则，按任务类型适用 |
| 6 | `复利与踩坑.md` | 经验参考，不具强制力 |

同级规则冲突时，取更严的一条。仍无法判定时，向用户提问，并把判定结果记入 `方法论日志.md`。

### 1.1 目录结构

```
<WORKSPACE_ROOT>/
├── Workspace/　　　　　　　← 规则中枢（六份核心文档 + 备份，不存项目产出）
│   └── Project/　　　　　　← 全部项目与归档（项目唯一存放位置）
│       ├── Project-001-名称/
│       │   ├── 背景情况.md　　　 ← 必填，按模板八项填写
│       │   ├── Token成本核算.md  ← 项目收尾统计
│       │   └── ...　　　　　　　 ← 该项目全部产出
│       ├── Project-002-名称/
│       └── Archive/　　　　　　 ← 已归档项目（只读）
├── 项目台账.md　　　　　　 ← 编号登记 + 项目状态总表（Agent 维护）
├── 理解日志.md　　　　　　 ← 每次任务的理解与确认记录（Agent 维护）
└── scripts/　　　　　　　　← 同步与维护脚本
```

约束三条：

1. 所有项目文件**必须**存入 `Workspace/Project/` 下对应的项目文件夹，禁止散落到桌面、下载或工作区根目录。
2. `Workspace/` 除 `Project/` 子目录外，只放规则文档与备份。
3. 新建工作区时，必须同时创建 `Workspace/` 与 `Workspace/Project/` 两个目录；此后新建的项目一律放入 `Workspace/Project/`，不再另建项目目录。

### 1.2 核心文档职责

| 文档 | 职责 |
|------|------|
| `agent.md` | Agent 最高优先级指令 |
| `全局工作台.md` | 总体规则、目录规范、行为铁律、命名规范、执行原则 |
| `复利与踩坑.md` | 记录错误、教训、可复用方法，避免重复踩坑 |
| `新项目流程.md` | 标准化项目启动流程，从需求到交付 |
| `工程的原则.md` | 代码/工程任务的执行基线 |
| `方法论日志.md` | 方法论的版本演变记录 |

### 1.3 工作区账本

两份账本放在工作区根目录，由 Agent 维护，用户可随时查阅。

**`项目台账.md`**：全部项目的编号登记与状态总表。列包括编号、项目名称、模式、状态、当前步骤、交付日期、修订截止、归档日期、备注。编号一旦分配不复用。

**`理解日志.md`**：每次任务中 Agent 对用户需求的理解，以及用户对该理解的确认。

| 字段 | 含义 |
|---|---|
| 日期 | 记录当天日期，格式 YYYY-MM-DD |
| 项目 | 项目编号与名称 |
| 条目 | 本轮理解的第几条，如「框架提问方向」「方案要点」 |
| 我的理解 | Agent 用自己的话复述的关键信息 |
| 用户确认 | 1 准确 / 2 部分准确 / 3 有偏差 / 4 不确定 |
| 结论或修正 | 确认后进入流程，或写下修正内容 |

- 写入时机：执行框架提问前、提交方案前、用户要求复述时。
- 确认方式：Agent 给 1–4 个数字选项，用户只答数字。
- 用户答 3 或 4 时，Agent 修正理解并重新提交确认，确认后才继续。

### 1.4 行为铁律（13 条）

1. 不得在未创建项目文件夹、未在 `项目台账.md` 登记的情况下开始任何实质性工作。项目文件夹只能建在 `Workspace/Project/` 下。
2. 每开启一个新任务，必须先执行 `新项目流程.md` 中的流程；模式由用户选择，用户不选时用阶梯模式。
3. 所有产出、中间文件、笔记，必须进入 `Workspace/Project/` 下对应项目文件夹。
4. 项目完成后，必须更新 `复利与踩坑.md`，沉淀经验。
5. 关键节点使用 `blindspot-audit` 扫描盲区，并补充到方案中；无该技能时，按 `新项目流程.md` 的内置盲点清单执行。
6. 项目收尾必须完成 Token 成本核算，记录到项目内 `Token成本核算.md`。
7. 交付后提供修订窗口：用户可在交付后 48 小时内提出修订需求，免费修订一轮。「一轮」的定义见 `新项目流程.md` 第 3.6 节。
8. 核心文档或账本修改后，运行 `scripts/sync_siwfa.sh` 同步全部副本，并生成当日备份 `YYYY-MM-DD+SIWFA工作区行为规范备份.md`。
9. 项目启动前必须执行技能策展：检索本地技能库和技能清单 → 查外部平台有无更好替代 → 择优汰旧。
10. 涉及代码/工程实现类任务时，进入「执行」阶段前必须先读 `工程的原则.md` 并遵循其原则。
11. 向用户输出的汇报默认遵循 STE 规范（详见 `agent.md` 第 4.7 节）。
12. 项目编号不复用。项目中止时在台账标注「阻塞」或「跳过」并写明原因，编号保留。
13. 修订窗关闭且用户确认收尾后，才可归档；归档后的档案只读，不再修改。

### 1.5 命名规范

- 项目文件夹：`Workspace/Project/Project-三位数字编号-项目名称`（连字符分隔），如 `Workspace/Project/Project-001-官网改版`
- 编号连续递增，不重复，不复用。
- 归档文件夹：`Workspace/Project/Archive/` 下沿用原项目名，编号不变。
- 文件命名：简洁描述，用下划线或中划线，如 `需求分析_v1.md`
- 备份文件：`YYYY-MM-DD+SIWFA工作区行为规范备份.md`；同日第二份追加 `-2`，如 `2026-10-25-2+SIWFA工作区行为规范备份.md`。

### 1.6 通用执行原则（9 条）

1. **杜绝主观臆断**：不猜测用户意图，不确定时追问确认。
2. **分层递进收拢需求**：从模糊到清晰，逐层确认。
3. **先预览再选择**：交付物先出预览，用户选定后再出完整版。
4. **以交付成果为核心导向**：不产出与交付无关的中间内容。
5. **可随时回退**：流程偏差时退回上一环节重新确认。
6. **全程中文沟通**。
7. **框架提问全部多选题**：每次最多 4 个问题；提问工具不可用时，改为编号问题，每题给 2–4 个选项。
8. **理解日志用数字选择题**：用户只答 1–4 的数字。
9. **规则冲突按第 0.2 节处理**：同级取更严，无法判定则提问并记入方法论日志。

### 1.7 归档规则

- 归档条件：修订窗已关闭，且用户明确表示收尾。
- 归档动作：项目文件夹移入 `Workspace/Project/Archive/`，台账写归档日期，状态改为「已完成」。
- 归档后：档案只读；需要继续开发时新建项目编号，不复活旧编号。

### 1.8 副本同步与备份

核心文档存在多份副本，以工作区 `Workspace/` 为唯一真源。

| 副本 | 位置 | 用途 |
|---|---|---|
| 真源 | `<WORKSPACE_ROOT>/Workspace/` | 日常执行 |
| 仓库副本 | `SIWFA/workspace/`、`SIWFA/skill/siwfa/references/` | 对外发布 |
| 已装技能 | 本地技能库 `siwfa/references/` | 技能调用 |
| 合并版 | `SIWFA/SIWFA.md` | 单文件分发 |
| 备份 | `Workspace/YYYY-MM-DD+SIWFA工作区行为规范备份.md` | 版本复原 |

- 同步由 `scripts/sync_siwfa.sh` 完成，禁止手工逐个复制。
- 个人内容用 `` 包裹。同步到公开副本时，脚本删除这两行标记之间的内容；备份保留全文。
- 信息图 `SIWFA信息图/siwfa-six-docs/source.md` 为快照，不参与自动同步；改动后需重建。
- 启动接入提示词不写入本文件，统一见工作区根目录说明、仓库 README 与 `siwfa` 技能的 SKILL.md。
